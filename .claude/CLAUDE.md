## AWS / GitHub の認証情報が必要な作業

- どのラッパーで起動したかは、システムプロンプトに追記される。追記が無いときは、通常のセッションとして扱う。
- 通常のセッション（`claude-safe`）では、AWS の資格情報（`AWS_*`）や GitHub の資格情報（`GH_TOKEN`）が必要な作業を行わない。
- 認証情報が必要になったら作業を止め、次の起動方法をユーザーに案内する。
  - AWS: `claude-aws <profile> -- <args>`
  - GitHub: `claude-gh -- <args>`
- `claude-aws` か `claude-gh` で起動したセッションでは、そのラッパーに対応する認証情報を使う作業を行ってよい。
  もう一方の認証情報が必要なときだけ、起動し直しを案内する。
- セッションの中から、起動方法自体を切り替えることはできない。案内後はユーザーが起動し直す。
- 認証情報の値を、ファイルに書いたり、コマンドに直接埋め込んだりしない。
- `~/.aws`、`~/.config/gh`、`.env` などの認証情報ファイルを読もうとしない。

## 変更の承認

- ファイルを変更する前に、変更内容の diff を提示し、承認を得てから変更する。
- `git add` と `git commit` の前に、必ず承認を得る。承認の前に、`git diff` で内容を確認できるようにしておく。
